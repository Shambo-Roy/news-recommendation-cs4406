# News Recommendation — CS4.406 Assignment 1

Reproducible lexical + semantic retrieval pipeline for news recommendation
on MIND and (later) EB-NeRD. Built incrementally, milestone by milestone —
see [reports/engineering_log.md](reports/engineering_log.md) for the full
narrative of design decisions, alternatives considered, and observations
behind every piece of this.

## Setup

Requires Python 3.11+ (developed against 3.12.10) and a Hugging Face
account with access granted to the [MIND dataset repo](https://huggingface.co/datasets/yjw1029/MIND)
(gated — register and request access there first).

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\pip install -e .
.venv\Scripts\huggingface-cli login   # one-time, interactive; needed before the pipeline can download MIND
```

## One-command rebuild

```bash
python scripts/build_pipeline.py --config configs/mind_small.yaml
```

This downloads MIND-small, cleans it into a common schema, assigns the
temporal train/val/test split with leakage checks, and materializes the
feature store — end to end, from nothing but the config file. Each stage
is also independently runnable (see below) and independently tested.

## Pipeline stages

| Stage | Script | What it does |
|---|---|---|
| 1 | `scripts/download_mind_small.py` | Fetch MIND-small train/dev from the authenticated Hugging Face cache |
| 2 | `scripts/audit_mind_raw.py` | Report raw file shapes/date-ranges/label sanity (no transformation) |
| 3 | `scripts/clean_mind.py` | Raw TSVs → common schema (`articles`, `impressions`, `interactions` parquet tables) |
| 4 | `scripts/split_mind.py` | Assign temporal train/val/test split; verify boundaries and no future-click leakage |
| 5 | `scripts/build_feature_store.py` | Attach split labels + cold-start/warm flag; materialize the feature store |
| 6 | `scripts/evaluate_random_baseline.py` | Sanity-check the evaluation harness against real data with random scores |

## Tests

```bash
.venv\Scripts\python.exe -m pytest tests/ -v
```

Tests that need the real downloaded dataset are skipped (not failed) if
it isn't present, so the suite stays runnable on a clean checkout.

## Project layout

```
configs/            YAML configs (paths, dataset choice, temporal split cutoffs)
data/                raw/ -> interim/ -> processed/ (all gitignored, regenerated by the pipeline)
src/news_reco/
  data/               per-dataset loaders + adapters -> common schema
  splitting/          temporal train/val/test split + leakage checks
  features/           the feature store
  retrieval/          lexical/ (BM25) and semantic/ (embeddings) candidate generation
  evaluation/          metrics (AUC, MRR, nDCG@k), bootstrap CIs
  reranking/          reserved for Component 2
scripts/             thin CLI entry points, one per pipeline stage
tests/               one test file per module
reports/
  engineering_log.md   running log of design decisions, observations, limitations
  design_note_c1.md    final <=4 page design note (written at the end)
```
